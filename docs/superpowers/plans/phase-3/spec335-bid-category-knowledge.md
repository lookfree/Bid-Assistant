# spec335 标书分类知识库：三类必备章节 / 必查项 / 行业资质补丁

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 逐任务执行。
> **依赖 spec334**：本 spec 只往 `prompts/categories.py` 的两张表里填内容，表结构与五个注入点由
> spec334 交付。spec334 可以先上线（表为空 ⇒ 全链路行为不变），本 spec 按条增补。

**Goal:** 沉淀「货物 / 服务 / 工程」三类标书各自的**必备章节**与**必查项**，以及按行业关键词触发的
**资质要求补丁**，让生成与审查带上通用提示词覆盖不到的行业常识。

**与 spec334 的分工：** spec334 是**一次做完的管线**；本 spec 是**持续增补的资产**，每条知识独立
验证、独立转正，永远不会有「做完」的一天。所以它不该阻塞管线上线。

## Global Constraints

- 作者 `lookfree <etwuman@126.com>`；禁止 Claude 相关内容。
- **必备章节一律是「投标文件」视角。** 招标文件自身的必备章节（投标人须知前附表、澄清与修改、
  质疑与投诉…）是采购人视角，与本功能无关，混进来会把整张清单带偏。
- **招标文件优先。** 必备章节只补招标文件**没提到**的章；`required_structure` 已给出的以它为准。
- **每条知识带三个属性：`status` / `依据` / `最后核验日期`。** `status` 只有两值：
  `待验证`（来自行业通行做法整理，尚未核到一手依据）、`已验证`（核到现行法规原文，或在我们自己的
  真实标书里确认过）。
- **`待验证` 的条目不得以「必备 / 必须」的口吻进提示词。** 措辞模板见下。
- **资质类条目核不到现行法规依据就不上线。** 这不是洁癖：本文件第一版就混进过一条已废止的
  （物业服务企业资质，2018 年随《物业管理条例》修订删除），照抄上线的后果是审查报告报一条
  「缺物业服务企业资质」的假风险，**用户信了会去补一个根本不存在的证**。
- 第三方来源与许可证记在仓库根 `NOTICE.md`。**转正的依据只能是现行法规原文或我们自己的真实标书，
  不能拿二手清单互相印证。**

## 措辞模板（`status` 如何影响提示词文本）

**本节是模板的权威定义，套模板的代码在 spec334 的 `category_scope()`。** 知识表里的 `text`
**只写要求本身**，不写两份文案——存两份每加一条要写两遍，还会写着写着漂掉。

| status | 模板 | 示例 |
|---|---|---|
| `已验证` | 「本标为<类>标，<text>」——祈使、无条件 | 「本标为工程标，施工组织设计必须含施工方案、进度计划、质量保证、安全文明施工四大块」 |
| `待验证` | 「<类>标通常<text>，**请核对本次招标文件是否有此要求**」——提示、可否定 | 「工程标通常要求施工组织设计含四大块（施工方案/进度计划/质量保证/安全文明施工），请核对本次招标文件是否有此要求」 |

理由：写手对提示词里的「必备」是无条件服从的。一条错的必备章节会让**每一本**标书都多出一章不该有的
内容，而用户看不出那是我们编的还是招标文件要求的。**错的清单比没有清单更糟。**

## Task B: 服务标知识

**必备章节骨架**（十章通用骨架，约八成服务标适用）

| 部分 | 章节 |
|---|---|
| 商务 | 投标函、开标一览表、报价明细表、中小企业声明函、法人授权委托书、营业执照及资质证书、业绩证明材料 |
| 技术 | 一、项目背景及需求分析（背景理解 / 需求分析 / **重点难点及对策**）<br>二、项目整体服务设想（总体思路 / 目标及原则）<br>三、组织机构及人员配备（组织架构 / 人员配置方案 / **人员管理：招聘·培训·考核·替换** / 拟投入物资设备）<br>四、**【核心服务方案】——按项目性质替换**<br>五、项目管理制度<br>六、服务质量保障措施（质量标准 / 质量控制体系 / **违约责任承诺 ★**）<br>七、应急预案<br>八、档案管理方案<br>九、服务承诺及投诉处理<br>十、同类项目业绩 |

> **第四章是唯一需要因项目而异的章**，其余九章是稳定骨架。这与「靠评分项反推」正好合缝：
> 读评分项 → 逐一匹配到骨架章节 → 评分项里的「服务方案/实施方案」部分替换第四章 →
> 评分项没覆盖到的骨架章节保底保留、简写即可。**我们不需要为每个服务子类型预置模板**——
> `prompts/outline.py` 第 5 条已强制「提纲覆盖评分办法表每个得分点」，这条路本来就通。

> **「违约责任承诺」单独标星**：多数服务标评标细则把它列为必备，遗漏即该项 0 分；而它既不在
> 技术方案里也不在商务条款里，是最容易整章漏掉的一条。

**必查项**

| 条目 | status | 依据 | 最后核验 |
|---|---|---|---|
| 人员配置覆盖招标要求的全部岗位与人数 | 待验证（**优先转正**） | 库里真实标已见佐证：某攻防演练标包件说明写明「人员要求：高级≥1人、中级≥1人、初级≥2人」；转正还需再取 2–3 份不同类型服务标确认普遍性 | — |
| 服务响应时间对标招标 SLA | 待验证 | 通行做法 | — |
| 关键岗位证书在有效期内 | 待验证 | 通行做法 | — |
| 中小企业声明函按**是否允许分包**决定填法：不允许 = 只填投标人自己一家；允许 = 须填全所有分包方 | 待验证 | 待核《政府采购促进中小企业发展管理办法》 | — |

**服务标特有陷阱：定人定薪（变相最低限价）**（`purpose=planning` + `review`）

招标文件若同时锁定「人员不少于 X 人」「月薪不低于 Y 元」「管理费比例固定」，属变相最低限价：
供应商无法通过管理优化降本，价格分实质失效，利润被锁死。

- 审查侧：提示用户评估**是否值得投**（利润被锁死），并核对三项是否全锁。
- 正文侧：偏离表 / 报价说明中保留调整空间的表述（如岗位配置按投标人最优方案、薪酬随行就市、
  管理费给区间）。
- status：`待验证`（来自二手合规分析，需核一手法规口径）。

## Task C: 工程标知识

**必备章节骨架**

| 部分 | 章节 |
|---|---|
| 商务 | 投标函、开标一览表、**工程量清单报价表**、材料价差表、主要材料表、中小企业声明函、保证金、法人授权、营业执照、资质证书 |
| 技术 | 一、工程概况及**施工特点难点分析**<br>二、施工组织设计（施工组织机构 / 施工总体部署 / **施工总平面布置**）<br>三、施工进度计划及保证措施<br>四、**主要施工方案——按分部分项展开**<br>五、质量保证体系及措施<br>六、**安全文明施工措施**<br>七、劳动力及物资计划<br>八、分包计划（如有）<br>九、竣工验收及回访保修<br>十、应急抢险预案<br>十一、对招标文件的响应及偏离表<br>十二、同类工程业绩 |

**第四章「主要施工方案」的展开规则**（工程标与其它两类差距最大的地方）：
按本工程实际包含的分部分项逐项成节——房建常见为 测量 / 土方 / 基础 / 主体结构 / 装饰装修 /
水电安装 / 脚手架 / 模板 / 钢筋 / 混凝土；**市政、道路桥梁、装饰装修工程各有各的分项，
不可照搬房建那一套**（与「招标文件优先」同源：分项清单以招标文件的工程量清单为准）。
**每个分项方案须含三件套：施工工艺流程、质量控制要点、安全注意事项。**

其余各章颗粒度：质量保证含质量目标（一次性验收合格率、工程质量等级）、三检制度（自检/互检/交接检）、
隐蔽工程验收、质量通病防治；安全文明施工含安全生产目标、安全管理体系、分项安全措施（高处作业 /
用电 / 机械 / 消防 / 基坑支护 / 脚手架）、文明施工（围挡 / 扬尘 / 噪声 / 污水 / 现场卫生）、环境保护；
劳动力计划按**工种**给人数与进退场时间，另附主要材料计划与主要机械计划。

| 条目 | status | 依据 | 最后核验 |
|---|---|---|---|
| 安全生产许可证在有效期内 | 待验证 | 待核《安全生产许可证条例》 | — |
| 项目经理建造师等级/专业与招标要求匹配且无在建冲突 | 待验证 | 待核《注册建造师管理规定》 | — |
| 工程量清单覆盖全部分部分项，无漏项与不平衡报价 | 待验证 | 通行做法 | — |
| 施工组织设计四大块齐全（施工方案 + 进度计划 + 质量保证 + 安全文明施工） | 待验证 | 通行做法 | — |
| 安全文明施工措施完整 | 待验证 | 通行做法 | — |

## Task D: 行业资质补丁表

`关键词命中 → 追加一条必查项`。**只做资质与陷阱，不做内容指导**——资质缺失是废标，且是模型从
招标文件正文里推不出来的行业常识；而「这行的方案该怎么写」有评分项反推兜底，不需要预置。

| 命中关键词 | 追加的必查项 | 级别 | status / 依据 |
|---|---|---|---|
| 劳务派遣 / 人力资源 / 劳务外包 | 须提供劳务派遣经营许可证与人力资源服务许可证 | 高 | 待验证 · 待核《劳务派遣行政许可实施办法》《人力资源市场暂行条例》 |
| 保安 / 安保 | 须提供保安服务许可证 | 高 | 待验证 · 待核《保安服务管理条例》 |
| 档案整理 / 档案数字化 | 涉密项目须提供国家秘密载体印制资质证书 | 高 | 待验证 · 待核保密资质管理规定 |
| 土壤调查 / 测绘 / 土地整治 | 须提供相应等级测绘资质证书 | 高 | 待验证 · 待核《测绘资质管理办法》 |
| 专职消防队 / 消防值守 | 关键岗位须持消防员职业资格证或消防设施操作员证 | 高 | 待验证 · 待核《消防法》及职业资格目录 |
| 食堂 / 餐饮 / 团餐 | 须提供食品经营许可证与从业人员健康证 | 高 | 待验证 · 待核《食品安全法》 |
| 检测 / 检验 | 须提供 CMA / CNAS 资质 | 高 | 待验证 · 待核检验检测机构资质认定管理办法 |
| 运维 / 系统集成 / 信息化 | 视项目要求提供 ITSS 等运维资质 | 中 | 待验证 · 行业通行 |
| 保洁 / 清洁 / 环卫 | 视招标要求提供清洁服务相关资质 | 中 | 待验证 · 行业通行 |
| ~~物业管理 / 物业服务~~ | ~~须提供物业服务企业资质~~ | — | **已废止，不得上线**：2017 年国务院分两次取消物业服务企业二级及以下与一级资质核定（国发〔2017〕7 号、46 号），住建部第 39 号令废止《物业服务企业资质管理办法》，2018 年国务院令第 698 号修改《物业管理条例》删去资质要求。现在只需工商注册即可经营 |

> **这张表的适用面比看上去窄，要有心理准备**：10 条全是**服务类**行业，货物类、工程类一条都没有；
> 且集中在物业后勤/传统服务业，只有「运维/系统集成 → ITSS」一条沾 IT 的边。对以 IT 采购为主的客户，
> 这张表当前**基本用不上**——IT 类的资质条目（等保测评、CCRC 信息安全服务资质、涉密信息系统集成资质等）
> 需要另行整理，是本 Task 最有价值的增量。

## Task E: 逐条转正（持续任务）

把 `待验证` 转成 `已验证`，一条一条来，**每转正一条就改一次措辞模板**（从「通常…请核对」变成
「必须…」）。优先级：

1. **两条中小企业声明函填法**（货物填所有制造商 / 服务按是否允许分包）——填反直接废标，
   是三分法最硬的价值点，也是最该先核准的。
2. **资质类全部条目**——政策最易变，且被定为「高」级别，报错直接误导用户。
3. 其余必查项与必备章节——可在真实项目里逐步印证。

**验证依据只认两种**：现行法规/国标原文；我们自己库里的真实标书。**二手清单不算依据。**

- [ ] Task E（每转正一批提交一次 `docs: verify <类别> category knowledge`）

## 验证口径

每条知识落库后，对应注入点的两态测试（有/无该条）须绿。归总：取真实标各类若干跑提纲与审查，
人工核对「补出来的章 / 报出来的必查项」是否确属该类标书要求，且**没有把行业经验报成招标明文要求**。

## 决策记录

- **不建行业知识层**：服务标子类型多到无法穷举（保安/保洁/食堂/会务/绿化/护工/救生员/物流/检测/
  品牌推广…），逐个建模是无底洞。行业维度只做「关键词 → 资质必查项」的补丁表，内容层面靠评分项反推兜底。
- **知识分级（`待验证` / `已验证`）而不是「全部验证完再上线」**：后者等于永远不上线。
  分级让管线先跑起来，知识按条增值。
- **资质类核不到现行依据就不上线**：本文件第一版就混进过一条 2018 年已废止的（物业资质）。
- **必备章节按主类别、必查项主次都给**（混合标处理，与 spec334 一致）：提纲结构只能有一套，
  查多了只多看一眼、漏了是废标。
