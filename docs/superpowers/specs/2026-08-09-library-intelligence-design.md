# 资料库智能化与所见即所得闭环 · 设计

2026-08-09 · 状态:已与用户对齐口径,待实施

## 背景

资料库当前只有两个自动利用点:正文 RAG 检索(概率命中)与导出时的资质附录(审查看不见)。由此产生两类问题(用户实测提出):
1. **审查偏离**:资质附录导出瞬间才附,审查跑在导出前 → 资格类要求被误报"缺失",用户被假阳性惊吓
2. **该自动的没自动**:人员信息/营业执照等,招标要求 + 资料库有货,却要靠 RAG 撞运气或人工手插

## 总原则(用户拍板)

**导出产物中的一切内容,要么是"系统章节"(生成期就存在,编辑器/审查/导出三者看到同一份),要么进"渲染恒定项注记"(审查被明确告知)。禁止第三种"只在导出时冒出来"的东西。**

自动注入的一切都是**确定性代码**投递(高确定性才动手,拿不准靠附录章兜底),模型不碰 fileId,人工永远可改可删。全部零新增计费。

## ① 资质附录前置为系统章节

- **触发**:content 步收尾(流水线交稿后、返回前),用户资料库存在 qualification 类条目且含图片附件,且 outline 尚无该章 → outline 追加系统章:
  `{id: "sys-creds", no: "附录", title: "资格证明文件", group: "business", system: true, sourced: false, items: []}`
  (App 侧 outlineChapterSchema 为 `.passthrough()`,`system` 键存活——已验证,不会重蹈 sourceFileId 被剥的覆辙)
- **章内容**:确定性 HTML——每个条目 `<h3>条目标题</h3>` + 逐图 `<img data-file-id="<fileId>" alt="<标题|OCR文字>">`(**无 src、无字节**;单张证照 base64 几百 KB,进 chapters 会撑爆检查点与 result 列)
- **占位图三端解析**:
  - 编辑器:加载章节后对 `img[data-file-id]:not([src])` 现取预签名填 src(预签名过期无所谓,下次加载再取)
  - 审查:`strip_inline_images` 现状即可(换成 ［图片：alt］,alt 携带 OCR 文字)——零改动
  - 导出:`render_docx` 图片分支扩展——`data-file-id` → MinIO 按 key 取字节(经 fileId→key 映射随 run_input 下发或渲染前解析);取不到 → 占位行"(图片加载失败:…)",沿用现有坏图语义
- **导出层退役**:`_append_credentials` 与 export 步的 credentialsRunInput 下发删除;分册规则"附录跟商务册"由 `group: "business"` 天然实现(技术册过滤自动排除);导出预告区的资质行改为按 sys-creds 章现状描述
- **时效性(无 DB 脏标记)**:编辑器加载时比对 sys-creds 章内 fileId 集合 vs `export-preview` 现查库存 → 不一致显示"资料库已更新,一键刷新附录"(免费,确定性重建该章)
- **用户主权**:它就是普通章——可编辑、可删单图、可整章删除;**重新生成正文(generation+1)会重建**(视为从头来过),失败重试不动它

## ② 渲染恒定项 → 审查注记

审查(review 节点)的模型输入追加一行系统注记:"导出时将恒定附加:封面、目录、投标人承诺与签章页、AI 生成说明页"。提示词规则:招标构成清单要求签章页/目录等命中恒定项时,判"已具备(导出恒定附加)"而非缺失。

## ③ 证照定向插章(高确定性才动)

- 词表(可扩展常量):营业执照/资质证书/授权书/法定代表人身份证明 等
- content 流水线 `_shared_blocks` 阶段:资格/商务类读标条目命中词表 + 经 structure_ref/clause_ids 定位到具体章 + 资料库有对应条目(条目标题命中同词) → 该章模型交稿后**代码**在章尾追加"XX见下图" + 占位图(同①的 `<img data-file-id>` 形态)
- 定位或匹配拿不准 → 不插(附录章兜底,宁可少插不错插)
- 要求有而库**无** → 该章留"(待补充:XX)"提示行 + **读标页前置预警**:"招标要求 XX,资料库未见,建议上传"(读标结果展示层,数据来自读标条目词表命中 × export-preview 同源库存查询)

## ④ 人员/业绩条目定向注入(纯文本)

- 库类别已有 personnel/performance(schema 枚举存在)
- content 流水线 `_shared_blocks`:章标题/子项命中"人员|团队|组织|配置|简历"→ 注入【资料库·人员】块;命中"业绩|案例|经验|项目经历"→【资料库·业绩】块
- 块内容:该类条目的 title + fields + body 摘要,结构化列出;预算上限(每块 ≤3000 字,条目数超限截断并注明,与偏离表条目预算同手法);写手提示词已有"化用参考资料"纪律,复用
- 与 RAG 并存:定向注入是保障,RAG 继续负责长尾

## 基建:附件 OCR 前置存储

- `LibraryAttachment` 增可选 `ocrText?: string`(jsonb 免迁移;**上传/保存链路的 zod schema 同步加该字段——sourceFileId 的教训**)
- 计算时机:图片附件上传 complete 后、PDF 转页图完成后,App API 后台 fire-and-forget 调 OCR 容器,结果写回附件;失败静默(alt 退化为标题|文件名,现状)
- 消费:①③的占位图 alt;编辑器手动插图路径优先用存量 ocrText(省一次现算)

## 计费

全部零新增计费:附录构建/刷新/定向注入是确定性代码,发生在已计费的 content 步内或免费操作;OCR 是内网自建服务。计费代码一行不碰。

## 测试概要

- agent:附录章构建(有货建/无货不建/重试不动/重新生成重建);render_docx data-file-id 分支(取到/取不到);③词表匹配与定位(命中插/含糊不插/库无留待补充);④注入块(命中章带/无关章不带/预算截断);②注记(构成要求命中恒定项不判缺——提示词测试)
- api:ocrText 往返(schema 不剥);OCR 后台任务 best-effort(失败不影响上传);export-preview 预告口径
- web:占位图预签名解析(纯函数可测部分);附录过期比对函数;刷新按钮

## 实施分两个计划

- **Plan A(先行,消偏离)**:① + ②——附录系统章节 + 导出层退役 + 审查注记
- **Plan B(智能注入)**:③ + ④ + OCR 基建
