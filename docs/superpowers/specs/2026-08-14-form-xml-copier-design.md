# 表单章复印机（XML 原样复刻 + 代码填空）设计

## 背景与问题

「表单格式与招标书一致」当前走的是**重建路线**：解析层把招标 docx 降维成纯文本 →
定位表单 → 模型照着文本模板填空 → 保真闸校验 → HTML 渲染 → docx 导出。链条第一步就
丢掉了版式（表格合并格、下划线空位、居中、缩进），后面全部环节都在凭文本残影逆向重建。

实测代价（2026-08 云上江西/潍坊两单）：表格聚合、合并格、落款靠右、抬头去重、标点全半角、
【】占位、表格空格子——每份新标书都暴露残影重建的新细节，修复收敛但封不了顶。同时模型
天性是改写机（规范化标点、加编号、拆分项、补说明），保真闸在「填空」与「改写」之间划线，
边界是无穷的 edge case。

## 目标

纯格式表单章的导出产物与招标文件**逐字节同源**（版式=复制而非重建）；资料库/项目信息里
有值的空位由**代码**填写（确定性匹配，绝不虚构）；模型彻底退出这类章的格式生产。

## 范围

**接管**：招标给定格式、要求原样提交的表单——响应函、法定代表人授权书、资格信用承诺函、
报价一览表、报价明细表、供应商情况一览表等（判定=现有模板定位引擎认出的表单章）。

**不接管**：偏离表（要逐条生成响应内容，本就在模板保真范围外）、方案/技术类散文章、
述标。`.doc` 招标文件经转换器有损后的版式损失不在本设计救治范围（上传侧已引导另存 .docx）。

## 架构（四个组件）

```
导出步（agent render）
  ① 取招标 docx 原始字节（run_input 的 tender file key → MinIO）
  ② 解析并建立「文本行 → body 节点序号」映射（复用解析层，新增映射输出）
  ③ 对每个未手改的表单章：模板定位（复用 form_locate）→ 行区间 → 节点区间
     → 深拷贝该区间 XML 进输出 docx（表格/下划线/居中天然保真）
  ④ 在拷贝出的节点上代码填空（企业信息七字段 + 项目信息白名单）
  失败任一步 → 该章回退现有 HTML 渲染路线（纵深，不新增失败模式）
```

### ① 定位映射（parsing）

`_docx_lines_in_order` 已按文档序产出 blocks；为每个 block 记录其**来源 body 子节点序号**
（段落=该 w:p 的序号；表格行=所属 w:tbl 的序号，多行同号）。clauses 由 blocks 派生，
沿既有路径把序号带到 `doc_sections` 的行级。`form_locate` 的切分结果从「行区间」升级为
可换算的「body 节点区间」（起止节点序号，闭区间）。

### ② XML 搬运（render）

- 打开招标 docx（python-docx），按节点区间深拷贝 `w:p`/`w:tbl` 元素（`copy.deepcopy`），
  插入输出文档对应章位置。
- 引用型依赖的处理：**V1 只搬内联属性**（表单版式绝大多数长在元素自身：tblBorders、
  gridSpan、jc、u）。元素引用的 styleId 在目标文档缺失时 Word 回退默认样式，可接受；
  检测到编号引用（numPr）时 V1 直接放弃复印、回退 HTML 路线并记日志（表单极少用编号列表，
  先不为它搬 numbering.xml）。
- 图片关系：表单模板内出现 blip 引用时同样回退（模板里基本不会有图）。

### ③ 代码填空（render）

值来源与匹配规则（全部确定性，匹配不上一律留白）：

- **企业信息**：复用 `bidder_profile.bidder_fields`（用户在资料库录什么标签就匹配什么标签，
  不做归一猜测）。
- **项目信息**：白名单三项——项目名称、项目编号、采购人名称（取读标 project_meta）。
- 空位形态与填法：
  - 段落型「标签：＋下划线 run/连续下划线」→ 替换该 run 的文本，**保留 run 格式**
    （填进去的字自带下划线，即纸面「写在横线上」的效果）；
  - 表格型「标签格 → 右侧空格子」→ 空格子写值；
  - 占位括注「（供应商名称）」→ 不替换（V1 保守：括注是提示语而非空位，替换歧义大）。
- 标签识别用与保真闸同源的宽度归一（全半角冒号/括号），但**写入内容永不改动模板字符**。

### ④ 接线与回退（App + agent）

- App 侧导出触发时，比较当前各章 HTML 与 content 步结果：一致的表单章标记
  `form_pristine`，随 run_input 下发；**用户手改过的表单章不走复印机**（尊重手改，
  走现有渲染），避免静默丢弃用户编辑。
- agent 导出步对 pristine 表单章执行 ①-④；任何异常（下载失败/定位不中/含 numPr/填空报错）
  → 该章回退现有 HTML 渲染，记 `form_copier_fallback` 事件（含原因），绝不让导出步失败面扩大。
- 观测：`form_copier_ok`（章、填空命中数）/`form_copier_fallback`（章、原因）进 agent_event_log。

## 编辑器语义（产品说明）

编辑器继续显示 HTML 近似版（现状）；导出以复印机产物为准。两者的差异边界向用户明示：
表单章预览为近似排版，导出以招标原格式为准；一旦手改该章，导出即以手改内容为准
（复印机对该章让位）。

## 验收

- 云上江西 + 潍坊两份真实标书从 DB 完整回放：导出 docx 的表单章与招标原文视觉一致
  （表格结构/合并格/下划线/居中），企业信息按资料库落位，无虚构填充；
- 手改章回退路径、numPr/图片回退路径各有测试钉住；
- 全量测试绿；两类真实形态（细粒度 PDF 模板无法复印 → 自然回退 HTML 路线）不回归。

## 风险与对策

| 风险 | 对策 |
|---|---|
| 样式/编号引用搬运不全 | V1 检测到即回退 HTML 路线并记日志，不追求全形态覆盖 |
| 行→节点映射在表单跨表格边界处偏移 | 区间按「起止行所在节点」取闭区间，宁多勿少；回放校验 |
| 编辑器所见与导出不一致引起困惑 | 表单章预览处加一句固定说明文案 |
| PDF 招标文件无 XML 可复印 | 判定源文件类型，非 docx 一律走现有路线（不减功能） |
