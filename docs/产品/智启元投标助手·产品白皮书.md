# 智启元投标助手 · 产品白皮书

**版本**：v1.0（对应产品版本 2026-07-29）
**适用读者**：企业决策者、投标负责人、信息化与采购部门、合作伙伴

---

## 一、我们要解决的问题

投标是一项高压、高重复、高风险的工作。一份中型项目的投标文件通常在 100–200 页、5–10 万字，从拿到招标文件到递交，留给投标团队的时间往往只有三到五天。在这段时间里，团队必须完成四件很难同时做好的事：

**读懂招标文件。** 一份招标文件动辄上百页，评分办法、资格条件、技术需求、格式要求分散在不同章节，还常常附带多个包件和补遗文件。人工通读一遍需要数小时，而漏掉一条带★的实质性要求，可能直接导致废标。

**组织出符合要求的文件结构。** 投标文件的章节构成由招标文件规定，顺序、编号、必备表单一项都不能少。不同项目要求不同，套用上一次的模板往往埋雷。

**把内容写实。** 评审专家最反感"换个项目名也照样成立"的套话。真正得分的内容需要锚定这个项目的具体条款、参数、场景，还要在有限篇幅里把分值高的部分写透。

**自查风险。** 递交前需要逐条核对是否有废标风险、格式是否符合、与既往标书是否高度雷同。这一步最容易因为时间不够而被跳过。

智启元投标助手把这四件事变成一条可控的流水线：**上传招标文件 → 解读 → 生成提纲 → 撰写正文 → 风险审查 → 述标演示 → 导出成文**。每一步的产出都可见、可编辑、可溯源，人始终掌握决定权。

## 二、产品定位

**一个由 AI 驱动、但由人做主的投标文件生产系统。**

我们不做"一键生成、拿来就投"的黑盒。投标文件是要签字盖章、承担法律责任的商务文书，任何一个环节的臆造都可能造成实质损失。因此产品的设计原则是：

- **每一步都可见**：AI 的每个中间产物（识别出的要求、提纲、每一章正文、风险清单）都完整呈现，不藏在流程内部；
- **每一步都可改**：提纲可以增删章节和小节、拖拽排序、改标题改编号；正文可以在线编辑、也可以让 AI 按指令重写单章；
- **每一条都可溯源**：识别出的每一项要求都标注它来自招标文件的哪一条，点击即可跳转原文对照；
- **缺材料就说缺**：AI 不编造资质、业绩、认证。信息不足处明确标注"（待补充：…）"，而不是用漂亮话糊过去；
- **明确标识 AI 生成**：导出的文件末尾恒定附带生成说明，符合生成合成类算法的信息标识要求。

## 三、核心能力

### 3.1 招标文件智能解读

支持一次上传多个文件（招标公告、主文件、技术规范书、补遗、附件），系统合并解读，产出结构化结论：

| 产出 | 说明 |
|---|---|
| 项目信息 | 项目名称、采购编号、采购人、预算、投标截止时间等 |
| 分类要求清单 | 技术、商务、资格三类要求逐条抽取，标注★/▲ 实质性条款 |
| 评分办法 | 逐项评分点与分值，映射到对应章节 |
| 废标红线 | 汇总可能导致投标无效的硬性条款 |
| 投标文件构成 | 招标文件规定的章节构成与必备表单清单 |
| 包件划分 | 多包件项目自动识别，一包一份投标文件 |

**逐条溯源**：每一条要求都带原文条款定位，界面左右分栏对照，点击条目即定位到招标原文。

**大文件工程化处理**：面向真实的大体量招标文件，解读采用分段并行处理与断点续跑机制——单轮失败不必从头再来，已完成的部分自动复用。

### 3.2 提纲编排

基于解读结论自动搭建技术标与商务标提纲，并对齐评分办法——**分值高的部分自动获得更多篇幅预算**。

提纲完全可编辑，且编辑结果贯穿后续所有环节：

- **三级结构**：章 → 节 → 小节，满足评分点密集章节的细化需求；
- **拖拽排序**：同层内自由调整顺序，编号自动重排；
- **组顺序可调**：部分招标文件要求商务标在前，一键切换，全链路跟随；
- **编号模式**：全文连续编号 / 技术标商务标各自编号，一键切换；
- **构成对齐**：招标文件要求的必备章节自动纳入，不遗漏。

### 3.3 正文撰写

AI 写作团队按提纲逐章撰写，遵循几条硬约束：

- **紧扣评分点**：详略跟着分值走，方案章写透，程序性章节精炼；
- **反套话**：要求每段论述锚定本项目的具体条款、系统名称、参数、指标、场景；
- **承诺可核查**：服务保障类内容必须给出分级 SLA、响应时限、人员配置等具体表格，禁止"及时响应、全力保障"式空话；
- **沿用招标格式**：招标文件自带的响应函、证明、一览表等格式，逐格复刻其表格与措辞；无法完全复刻处**主动标注差异**，提示用户对照原文核对；
- **偏离表逐条落表**：技术/商务偏离表按固定列式产出，★/▲ 条目不得归并、不得遗漏；
- **篇幅可控**：用户设定目标字数（系统按预算规模与排版给出建议值），系统按评分权重拆分到各章执行。

正文支持在线富文本编辑、从资料库插入内容、插入图片，以及**按指令重写单章**。

### 3.4 风险审查与查重

**废标风险审查**：对全文做合规体检，输出 0–100 分的体检分、高/中风险清单与通过项，每条风险附整改建议与定位。

**标书查重**：多维指纹比对，识别与既往标书的雷同段落。以句级相似度为主分，图片指纹与元数据命中作加分项；**自动剔除对招标文件的法定引用**，避免把必须照抄的条款误判为雷同。支持快速/标准/严格三档策略。

**定制审核表**：根据本项目招标文件自动生成针对性的终审核对表，替代通用清单。

### 3.5 述标演示

将投标文件提炼为述标 PPT，包含逐页要点与口播稿，并预生成评委问答要点。支持按 10/15/20 分钟时长组织，可套用企业自有 PPT 母版。

### 3.6 导出成文

一键导出符合投标惯例的完整 Word 文件：

- **封面 + 真目录域 + 页眉页码 + 签章页**，目录随 Word 打开自动更新页码；
- **规范排版**：正文宋体小四、标题黑体纯黑（招标文件常见硬要求），字体/字号/行距/页边距均可自定义；
- **真实层级**：章 → 节 → 小节在 Word 导航窗格中层次分明；
- **资质附录**：资料库中的资质证照自动生成"资格证明文件"附录；
- **同步产出 PDF**，并回报文件的真实页数。

**导出始终基于当前内容**：任何编辑、AI 改写、提纲调整都会在下次导出时体现——不存在"下载到旧文件"的可能。

### 3.7 企业资料库

沉淀企业的资质证书、业绩案例、人员信息、技术方案等素材。写作时可作为参考资料被检索引用，也可在编辑器中直接插入。资料按用户隔离，仅本人可见可用。

## 四、技术架构

### 4.1 分层设计

```
        用户前端（C 端）          运营管理后台
              │                        │
        ┌─────┴────────────────────────┴─────┐
        │   应用服务层（业务 / 账务 / 鉴权）    │
        └─────────────────┬──────────────────┘
                          │
        ┌─────────────────┴──────────────────┐
        │  智能体服务（文档理解与生成工作流）    │
        └─────────────────┬──────────────────┘
                          │
        ┌─────────────────┴──────────────────┐
        │   数据层：关系库 / 缓存 / 对象存储     │
        └────────────────────────────────────┘
```

**账务与智能体严格隔离**：所有计费、鉴权、账本操作只发生在应用服务层；智能体服务只上报资源用量，不接触任何金额与余额。这条边界从架构上杜绝了"生成逻辑出错导致乱扣费"的可能。

### 4.2 生成工作流

投标生成是一条有状态的多节点工作流：**解读 → 提纲 → 正文 → 审查 → 述标 → 导出**。每个节点产出后暂停，等待用户确认后再推进下一步。工作流状态持久化，用户随时可以离开、换设备、隔天再回来继续。

### 4.3 工程可靠性

面向真实大标书的长时任务，系统在以下方面做了专门设计：

- **模型调用韧性**：流式调用 + 空闲超时判活 + 多模型降级链重试。慢而健康的长轮次不会被误杀，真正的连接挂死会快速切换备用模型；
- **断点续跑**：解读等分段任务的中间结果持久化，重试时复用已完成部分，不重复消耗；
- **任务自愈**：后台对账机制定期核查异常中断的任务——已成功的补齐交付，确实失败的自动全额退还积分；
- **切页不断流**：生成过程中切换页面或关闭浏览器，任务在服务端照常运行，回来自动接续显示进度；
- **计费幂等**：每次操作携带幂等键，网络重试不会重复扣费；任务失败一律全额退还。

### 4.4 模型策略

系统不绑定单一模型供应商。主模型与降级链由运营侧集中配置，可随时切换。模型配置缺失时系统明确报错而非静默回退，避免"用错模型还不知道"。

## 五、安全与合规

| 维度 | 措施 |
|---|---|
| **数据隔离** | 项目、资料库、生成结果均按用户隔离；跨用户访问在服务端拦截 |
| **权限控制** | 会话令牌鉴权；账号封禁在鉴权入口即时生效（含已登录会话）；运营后台独立身份与角色权限 |
| **内容安全** | 交付前敏感词扫描（记录不拦截）；生成内容明确标识 AI 辅助生成 |
| **算法合规** | 已按生成合成类算法备案要求整理完整材料：算法架构、流程、数据流向、接口、模型来源、测试评估、审核风控、日志字段、权限控制、第三方 API 说明 |
| **不训练用户数据** | 系统仅调用第三方大模型推理接口，不使用用户上传的招标文件或生成的标书内容训练模型 |
| **传输与存储** | 文件对象存储独立部署；生产环境支持全链路 HTTPS |
| **审计** | 关键操作与账务变动全程留痕，账本为只增不改的流水结构 |

## 六、部署与交付

支持三种交付形态：

| 形态 | 说明 | 适用 |
|---|---|---|
| **公有云 SaaS** | 开箱即用，按会员与积分计费 | 中小企业、个人投标人 |
| **私有化部署** | 全套服务部署在客户自有服务器，数据不出域 | 对数据敏感的政企客户 |
| **专属实例** | 独立环境与资源，可定制模型与流程 | 有特殊合规或流程要求的大客户 |

私有化部署的全部组件均可自建（应用服务、智能体服务、关系库、缓存、对象存储、向量检索），不依赖任何外部托管服务。硬件规格与网络要求可提供标准清单。

## 八、我们的取舍

有几件事我们**刻意没有做**，在此明示：

- **不做"一键出标、无需审阅"**。投标文件承担法律责任，产品的目标是把人从重复劳动中解放出来，而不是替人签字；
- **不编造材料**。缺资质、缺业绩、缺认证一律显式标注待补充，绝不用似是而非的表述掩盖；
- **不把自创格式伪装成招标模板**。未能在招标文件中检索到格式原文时，明确提示用户对照原版核对；
- **不在生成侧碰钱**。智能体服务对金额完全无感知，从架构上排除计费错误的一整类风险。
